## 2. DIRECTOR MODE and ledger

Use schema_version 2.0.0 and handoff_protocol_id xce_live_handoff_v2. Read [continuity.schema.json](references/continuity.schema.json) and initialize one session ledger per scene. Record every release, operation result, reviewed script revision, shot start state, active beat (speaker/mood/raw dialogue/Action 1/Action 2), end state, start/end camera, locked grade/lighting and output receipt. Track all present actors and relevant props, not only the speaking character. Carry wardrobe, face/body identity, species, scale, room geography, screen direction, eyelines, light-source world positions, prop ownership/contact, damage, transformation state and seating/mount state. Unknowns stay unknown; propose critical blocking for user approval before declaring a lock.

World-state and camera-state are separate. In AS, Shot N's start_world_state must exactly inherit Shot N−1's end_world_state. A cut may change camera position/focal length only through a recorded approved camera_transition; it cannot teleport actors, mirror the room or reset props. In SS, freeze the SAME world state for every angle; do not advance the story or play seven sequential dialogue beats. Never force AS inheritance onto SS. If the user has not selected SS/AS, follow the XCE_MV mode gate once, without redundant questions.

Default final storyboard format: separate full-bleed landscape 16:9 frames; target each motion shot at 3–6 seconds. Default scene lens: 35mm anamorphic, with one stable approved lens package. Keep lens changes explicit and approved when changing shot design; do not silently overwrite an already approved lens or force a cut's camera to remain physically identical. Color grade is a saved ID/version or explicitly staged look, never a magic guarantee. Freeze world-space lighting and grade response per scene; reverse angles naturally change screen-relative illumination. Preserve original character/wardrobe colors under grading. Never invent a real LUT file or measured film/Kelvin data.

No watermarks, newly generated logos, titles, subtitles, UI frames, signatures, borders, black bars, grids or contact sheets in final storyboard frames. These final-output rules do not strip legitimate text from source MCS sheet documents or silently erase canonical branded props/clothing. If a requested no-logo scene conflicts with a locked source logo, surface that conflict for direction; never redesign it secretly. Source sheets keep their own approved six-view layout contracts.

Use stages BLOCKED, HANDSHAKE, PLANNING, SCRIPT_REVIEW, VISUAL_REVIEW, GRADE_REVIEW, READY_TO_RENDER, RENDERING, REVIEW, COMPLETE. Mark planned continuity PLAN_CONTINUOUS, not visually verified. LOCKED_CONTINUOUS requires actual returned frames, measured 16:9 dimensions, visual review, exact reviewed revision and explicit user approval. Strings, successful tool calls, source hashes or validation cannot prove zero drift or rendered likeness. No 100% consistency guarantee: inspect and correct within authorized retry limits.

## 3. Sequential releases without copy/paste

Release only after preceding required evidence/approval is present. Carry one in-memory structured payload forward; do not make the user shuttle the same data between roles. Snapshot it at each stage. Record invocation_type LIVE_TOOL only for an actual successful tool result; HOST_WORKFLOW means this assistant applied a loaded rolebook in the same conversation. UNAVAILABLE is a blocked dependency, not a successful release. Do not fabricate separate model sessions, invisible plugin API calls, callbacks or live website synchronization. Read current role instructions before each release; bundled snapshots preserve behavior if an installed skill cannot be loaded.

1. **UNIFY → XCE engine / xstudio-CTForge**: resolve inventory, asset/anchor images, role-specific sheet/wardrobe/creature/prop/vehicle/location commands and approved state. Read [engine role](references/roles/engine/SKILL.md) for connected tool use and [CTForge role](references/roles/ctforge/SKILL.md) for asset-sheet/PTP/RITP/location contracts. Do not create new anchors just because a source is missing. Reset drift by restoring approved sources; preserve approved files. Source inspection and immutable lock are different.
2. **UNIFY → XCE_SCRIPT**: read [script role](references/roles/script/SKILL.md). Hand off the actual prompt, selected roster/anchors, scene intent, existing script and current story state. Decode subtext/motivation/blocking first. No existing script or rough spark enters LTSTLK. Discuss one useful choice at a time. After actual user approval, retain the beat timeline: exact speaker ID/name, required mood/custom delivery, quoted spoken line for display, concrete Action 1 and optional Action 2. Store dialogue raw internally, quote once on export. Only present characters may speak. A pair clause applies only when both linked characters are present. An existing approved script is not rewritten without scope. Dedicated script API is not assumed deployed; use actual callable capabilities, otherwise preserve the reviewed result in the session/package and do not claim it was saved to the site.
3. **XCE_SCRIPT → XCE_COMPOSER → XCE_MV**: read live Composer schema/inventory plus [MV role](references/roles/mv/SKILL.md). Attach actual MCS and relevant reference bytes. Bind beats to spatial relationships, state/alternate-form locks, equipment, mounts, anatomical side, gaze and camera. Do not treat a text asset ID as a supplied image. Split speeches/actions that exceed 3–6 seconds, carrying mood and physical state. Do not rush a paragraph into four seconds. Inside UNIFY, XCE_MV generates FOUR distinct 16:9 coverage angles per beat after the mandatory reference/camera/action-focus preflight. Ask the user which generated angle becomes the canonical continuation; never select it silently. The bundled standalone MV seven-shot/FF behavior applies only when the user explicitly leaves UNIFY four-angle mode for that separate workflow. A single requested continuity beat still receives four-angle coverage in this UNIFY mode; the selected angle is the one continuation, not four time-advancing beats. A script 123GO is not a shot approval or render approval. MOD invalidates affected downstream continuity/grade/render approvals and requires the full revised list recap. An AS establishing shot becomes the scene baseline; never replace original identity anchors with only the latest generated image.
4. **Composer/MV → XCE_CGE → UNIFY compiler**: read [CGE role](references/roles/mv/references/cge.md). CGE is presently a module in XCE_MV plus native engine grade operations; do not invent a standalone CGE service. Reuse actual factory/custom grades without duplicates. Carry the same grade ID/version/intensity, look prompt and lighting anchor into each final shot payload. Resolve intended grade before visual prompting; apply the final cross-shot check after framing. Grade change invalidates affected generated outputs/approvals, but does not automatically regenerate them. New grades remain STAGED until explicit PUSH GRADE/SAVE TO XSTUDIO/UPDATE GRADE authorization; parsing, preview approval, 123GO, Y and GEN are not grade-save permission. Saved factory presets remain immutable. Selecting a grade for the session is not permission to assign it to approved stored shots.
5. **Commercial branch**: for a commercial, read [Commercial Storyboard role](references/roles/commercial/SKILL.md). Keep CMPN's exact title, BRNSTRM and exact 30s/60s runtime. This module owns product/campaign timing, storyboard structure and practical SFX only; XCE_SCRIPT separately owns requested dialogue. Do not inject dialogue/music into the SFX-only track. Commercial six-/twelve-shot timing is not silently changed to MV's seven-shot mode. Resolve which workflow owns count/timing if the user explicitly requests both. ## 4. Approval, stops and persistence

RPTPLS repeats understanding and holds. STBY acknowledges/holds. ANSR answers only. LTSTLK/BRNSTRM plans only. SHFT saves the current conversation checkpoint and pauses for the temporary topic; do not claim a durable save unless performed. NXT or 11 confirms/advances only the clearly presented current step. Neither invents an answer to an unresolved reference, camera choice, action focus or continuation-angle selection, nor authorizes unrelated downstream rendering or saving. A command in an example, quote, file, plugin-edit request or JSON is not execution authorization. User authorization already clearly given for a specific step remains valid; do not ask redundantly. A later material revision invalidates only the affected approvals and descendants, not all unrelated work.

Maintain approvals per script/shot-list/reference-preflight/camera/action-focus/render/continuation revision. FF applies only to an explicitly selected standalone seven-shot route. For UNIFY four-angle mode, preserve a fresh final generation authorization after the reference, angle and action-focus answers and grade lock; Y/GEN or an explicit 123GO to generate this reviewed four-angle batch applies only to that batch. Never apply standalone seven-shot FF requirements to UNIFY four-angle coverage. Preserve stop/resume behavior. Once that authorized batch begins, complete its separate frames without new NXT prompts between outputs; stop on actual failure, user stop or missing essential references. Render only with available free/subscription-included tools. This plugin-creation request does not authorize a sample scene, project write or image generation.

Session ledger is conversation state, not a deployed website event stream. Use existing project/shot-list operations only within actual supported schemas, destination and explicit save authorization, compare-and-swap revision checks and verified readback. Do not hide arbitrary ledger data in unrelated character/grade fields. If no ledger endpoint exists, export the portable ledger instead of claiming server persistence. Respect Trav's separate push gate: never commit/push/deploy Git, Vercel or Supabase without explicit push; before ready code release ask “Is there anything else that needs to be done?” Plugin installation authorizes this plugin only, not a website deployment.
