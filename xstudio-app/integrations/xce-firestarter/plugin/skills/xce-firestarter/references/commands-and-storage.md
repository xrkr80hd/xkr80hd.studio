# World Builder connection

This package reuses the verified XCE app dependency. A plugin skill does not deploy its website API. Discover available tools before calls; do not invent a FIRESTARTER endpoint. Canonical project source: https://xstudio.xrkr80hd.studio. The app's historical Site host is connector infrastructure, not another project database.

1. Find the actual project by its user-selected name through the connected XCE project inventory; preserve exact IDs. Never choose the first project or change the active project merely to test access. Respect folder locks and ownership.
2. Read it with the available `manage_record` tool, `entity=project`, `action=read`, `project_id=<resolved ID>`. Use the returned record and revision. This does not read all historical chats. Retrieve relevant named history only when available and needed.
3. Read `record.world_builder`: `world_type`, `aesthetic`, `world_background`, `story_so_far`, `production_brief`, `notes`, and optional `firestarter_state`. Use the narrative schema for structured state. Missing fields do not mean the project is empty; inspect existing saved story/character material before constructing an update.
4. On US, compile only agreed facts in the story fields, with proposals and unresolved questions explicitly separate in the ledger. SS can create a real named project only when requested. For a real new title use the actually available create_project tool and its current schema; a URL alone does not create a project.
5. The implemented World Builder update contract is `manage_record(entity=project,action=update,project_id=<ID>,expected_revision=<fresh revision>,data={world_builder:<changed fields>})`. This website contract may still be awaiting Trav's explicit push and deployment. Until supported, do not assert save capability. For an authorized US, an unsupported-field failure means return the full handoff and report prepared but not saved; do not repurpose name/description or retry other projects. No write probes on startup.
6. Read the same project back after a successful update. Compare every changed field and exact project ID. A conflict requires re-reading and preserving any newer edits; never blindly overwrite. Report the actual returned status/revision and outstanding limitations. The full project data remains owner-private; a private plugin is not a special encrypted chat vault.

Text limits: world_type 1,000; aesthetic 5,000; world_background 30,000; story_so_far 50,000; production_brief 30,000; notes 10,000 characters. `firestarter_state` supports 200 entries (3,000 characters each), recap 30,000, up to 100 questions (2,000 each), total serialized state 180,000 characters. Exceeding limits requires an explicitly saved private checkpoint file plus its actual reference, never silent truncation. Preserve prior story when adding later developments. This protocol does not grant rights to approve anchors or change cast assignments without a current user instruction.

When site writes are unavailable, output a handoff containing `plugin_id`, `version`, exact `project_id` (or null if not selected), `status: PREPARED_NOT_SAVED`, the World Builder fields, current narrative ledger, and next handoff target `@XCE_UNIFY`. Provide a JSON download through available file tools when feasible. Read the applicable file-tool instructions; do not claim the file is durable until it has actually been saved. No private story content belongs in this plugin's source.
