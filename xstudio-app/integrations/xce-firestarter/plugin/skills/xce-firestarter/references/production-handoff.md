# Production handoff and supplied transfer notes

XCE_FIRESTARTER is the creative preparation stage. XCE_UNIFY boots the production sequence, audits the current XSTUDIO package and maintains its continuity ledger. Preserve XCE_SCRIPT, XCE_COMPOSER, XCE_MV and XCE_CGE, plus the existing XCE Engine / CTForge anchor and Commercial Storyboard routes. Do not omit a discovered role or treat FIRESTARTER as a replacement for those engines.

Carry the current story checkpoint, approved facts, unresolved proposals, actual roster IDs, chosen scene intent, aesthetic and world rules into UNIFY. Saved visual anchors override remembered appearance. No-script work remains LTSTLK until approved. Respect the UNIFY four-angle MV preflight and continuation-choice protocol rather than globally changing standalone MV defaults. Output targets remain 16:9 standalone frames, 3–6-second shot units, exact start/end physical continuity, isolated dialogue/shot prompts and consistent lens/lighting/grade. No watermarks or text overlays.

The supplied xtsudio.json PDF describes image generation and Lost Assets transfer instructions, not a proven synchronization service. It reports image transfers as unverified and requires inspecting live tool contracts. Keep those distinctions when UNIFY receives the project:

- Planning is not rendering; explicit generation authorizes generation under the relevant role's rules.
- Actual source image bytes are required when generating from saved asset codes. Never guess their appearance.
- Use only authorized free or subscription-included generation; no paid generation credits.
- If authorized generation produces images, deliver them and save each final output separately through an actually supported bytes route, to `xce-lost-assets` unless the user gives another destination. Never switch the active creative project to save to the shared pool.
- Preserve supplied names and order; do not invent character names. A multi-image workflow needs separate files, not a combined grid.
- Verify destination records before reporting saved. Generated, registered, saved, verified and approved are different states.
- Report per-file failures and partial completion truthfully; an image shown in chat, a URL and accessible bytes are not interchangeable. An uncertain retry must not silently duplicate output.

The PDF's historical host does not override the user's current canonical https://xstudio.xrkr80hd.studio source. This package does not claim that the previously inconsistent image transfers have been fixed.
